# checksim: smart checking and the background watcher, measured without paid APIs

Generated 2026-11-10T11:05:04Z, seed 20261110. `go run ./cmd/checksim -seed 20261110` in `freshness-companion/` reproduces every number.

**What runs.** The real `evidence.Cache`, `watch.Schedule`, `watch.Watcher` and `decision.Engine` on a virtual clock. A fake page states the Acme Pro price and follows a trace (49, then +10 at each change). Requests arrive as a Poisson process (whole seconds); each asks one of a few questions that share the fact, so there are a few Bifrost entries with deterministic ids. A miss writes the model's answer (the true current value) and runs the new-answer check; a hit is decided against evidence exactly as the proxy does, including the correction rule (`on_contradicted: correct`), which rewrites a right answer with a stale evidence value when the evidence is older than the page. No model call is simulated as costing anything; only evidence fetches are counted.

**Columns.** fetches = evidence fetches (request / watcher split); waited = requests that had to wait for a fetch; stale = answers served that state a value other than the page's value at that moment; refreshed = hits found stale and re-asked; corrected = answers rewritten to the evidence value; evicted = entries the watcher deleted; skips = watcher checks skipped over the hourly cap; lag = time from a page change to the first fetch that saw it (worst / mean).

## Assumptions

- Tavily credit rate, if these fetches were Tavily Extract calls: basic extract costs 1 credit per 5 URLs, so credits = fetches / 5. The default docker stack uses the direct provider, where a fetch costs nothing but a local HTTP GET.
- The model always answers the true current value on a miss or refresh. A real model can be wrong; that is a separate problem (the new-answer check and the audit) and is not measured here.
- Arrivals are Poisson and rounded to whole seconds; the watcher ticks once per virtual second. Nothing runs concurrently in the simulator, so a watcher fetch never coincides with a request fetch.
- The caps and floors are the flag defaults (`-evidence-ttl 5s`, `-check-max 5m`, `-check-growth 2`, `-watch-idle 30m`) except the watcher cap, which is the docker default `WATCH_MAX_PER_HOUR` 120 (the flag's own default is 60); they are not the docker `CHECK_MAX` default of 60s. A 60 s cap saves less and goes stale for less long.
