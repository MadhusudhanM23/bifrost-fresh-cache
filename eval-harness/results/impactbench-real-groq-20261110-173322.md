# Impact benchmark: Bifrost alone versus Bifrost with the freshness companion

## Read this first (added by hand, 2026-11-10)

This is the same benchmark as `impactbench-20261105-123632.md`, run once against a **real model**: `groq/openai/gpt-oss-20b` on Groq's free tier. Everything below this note was written by `impactbench` itself.

- **Embeddings are still the mock** (`mock-embedding`, a bag-of-words hash served by tools/mock-openai). Only the answers are real. Which questions the cache treats as "similar" is therefore decided exactly as in the mock run, including the two-factor on/off pair that scores 1.0.
- **Settings that differ from the mock run, and why:**
  - 1 run instead of 3 (a budget of 150 model calls for the whole exercise), so there is no median and no run-to-run spread.
  - Companion: background audits **off** (`-audit-rate=0 -audit-near-margin=0`; in the mock run every semantic hit was re-asked) and the pre-serve gate compares answers with a **model judge** (`-audit-compare=judge`) instead of exact text, because two real answers never match word for word and an exact compare would call every cached answer "different". Each gate check is therefore 2 model calls (a fresh answer and the judge), not 1.
  - Requests carry `max_tokens: 800` (this reasoning model returns an empty answer without room to think) and an assistant `tool_calls` message before each tool result (Groq rejects a tool result without one; the mock accepted it). The mock run sent neither.
  - Answers are judged by `-truth context` (a price answer must state the price in its own request's context; a cached FAQ answer must have been written for a question with the same meaning) instead of an exact compare with a fresh call, and model calls are counted from Bifrost's `/metrics` (`-calls-from bifrost-metrics`) because the real model has no counter the harness can read. No extra ground-truth calls were made.
  - Pacing for the free tier: 5 s pause after every non-cached response (`-write-gap 5s`, mock run 250 ms) and 60 s after each page change (`-settle 60s`, mock run 6 s). Because requests are now at least 5 s apart, the plain-ttl arm uses a **30 s TTL** instead of 5 s; with 5 s every entry would have expired before the next request and the arm would only have measured misses.
  - The stack was a separate throwaway Docker Compose project (`realbench`, ports 18590/8590/8591/18580/5439) with the same images and the same Bifrost semantic-cache settings as `docker/bifrost-config.real.json`, so the owner's running stack was not touched.
- **Model calls used: 91 chat requests were sent to Groq, 83 of them answered** (2 sanity checks before the run, then 12 in the plain arm, 37 in the companion arm, 32 in the plain-ttl arm) **and 8 refused with HTTP 429** (rate limit on tokens per minute, all in the plain-ttl burst; they appear as errors in that arm and are not in its model-call row). One more call listed the provider's models at start-up. Counted from Bifrost's `bifrost_upstream_requests_total` (chat requests with a provider key) and `bifrost_error_requests_total`.
- **What makes the comparison imperfect:**
  - The 8 errors in plain-ttl are a free-tier artefact: 16 simultaneous misses exceed Groq's 8,000 tokens-per-minute limit. A paid tier would have answered them, and plain-ttl would then have had 5 bad answers (the wrong matches), not 13. The companion was not hit by the limit because it made 5 calls for the 16 concurrent asks.
  - The companion's burst took 5 model calls here against 1 in the mock run: with a real call taking 0.5-1 s, not every concurrent request joined the one shared refresh.
  - Latencies include a real model call over the internet for every non-cached request (p50 about 0.5 s, p95 1-2 s), so the plain arm's p95 is also in the seconds now. Cache hits that need no check stay at about 4 ms in every arm.
  - One run, one seed; a real model's wording also varies from call to call. Read the counts as "what happened once", not as rates.
  - Judging by context trusts that the model states the price it was given; the 2 sanity calls before the run showed it doing so, and every fresh price answer in the run stated the context price.

## What was measured

A support bot answers price questions. Its app puts the **current** price into the system message at request time, and a demo page is the source of truth for that price. The same scripted request list is replayed against each arm, one arm completely after the other, with the first arm changing from run to run.

1. **Warm**: price questions in several wordings, plus each look-alike pair (A then B) and two ordinary questions, with the page at $49.
2. **Change**: the page is set to $59 and the harness waits 1m0s (longer than the companion's evidence cache).
3. **After the change**: the same and new price wordings (now with the $59 context), look-alike pairs in the opposite order (B then A), same-meaning rewordings, ordinary questions, and 4 requests that carry a role "tool" message (the same question twice with a different tool result).
4. **Burst**: the page is set to $69, the harness waits 1m0s, then 16 identical price requests are released at the same moment at the now-stale entry.

Answers come from a real model (`groq/openai/gpt-oss-20b`), so the wording changes from call to call and an exact text compare would call almost everything wrong. Answers are judged without extra model calls instead (`-truth context`): **Right answer** = for a price question, an answer that states the price in that request's own context; for any other question, a fresh answer, or a cached answer that was first written for a question that means the same. **Stale** = a price question answered with a different price. **Wrong match** = a price question answered with no price, or a cached answer first written for a question that means something else (for example the other half of a look-alike pair). **Error** = not HTTP 200 or an empty answer. **Bad answer** = stale, wrong match or error.

Arms (each uses its own cache key in every run, so no two arms ever share cache entries):

- **plain**: Bifrost alone, `http://127.0.0.1:18590`
- **companion**: Bifrost + freshness companion, `http://127.0.0.1:8590`
- **plain-ttl**: Bifrost alone, short TTL 30s, `http://127.0.0.1:18590`, extra header x-bf-cache-ttl: 30s

## Honest limits

- Answers come from a real model (groq/openai/gpt-oss-20b) on a free tier; the embeddings are still the local mock (a bag-of-words hash). So which questions the cache treats as "similar" is decided by shared words, exactly as in the mock run, and look-alike pairs reach the cache only because the mock embedding scores them high. A real embedding model would score some pairs higher and some lower. Do not read any rate here as a rate for real traffic.
- The workload is small and scripted (see "Workload"). The per-1000 rates are the counts of this one story scaled to 1000 requests, not a forecast. With a single run there is no run-to-run spread at all, and a real model adds its own randomness.
- No ground-truth model calls are made. A price answer is right when it states the price that its own request's context gives (the sanity check before the run showed the model doing this); a model that ignored its context would be counted as stale here even on a fresh call. Any other answer is judged by where it came from: a fresh answer is right, and a cached one is right only when the client saw it written for a question that means the same (see MeaningGroup in workload.go). This catches look-alike mix-ups, not every way a real answer can be poor; answer quality itself is not judged. Tool-result requests are reported as reused from the cache or not, not as right or wrong.
- The companion's settings differ from the Docker demo used for the mock run: background audits are off (-audit-rate=0, -audit-near-margin=0) because each one is a paid model call and they only report a wrong match after it was served, and the pre-serve gate compares answers with a model judge (-audit-compare=judge) because real answers never match word for word. So each gate check costs two model calls (a fresh answer and the judge). See "Settings".
- FAQ and look-alike requests carry no system message, as in the mock run.
- Model calls are counted from Bifrost's own Prometheus counter bifrost_upstream_requests_total (chat requests that Bifrost sent to a provider with a key; cache hits carry no key and are left out), as a difference before and after each arm, after waiting for background work to finish. Embedding calls are counted by the mock, which serves them. The command checks that the counters are idle before starting.
- Free tiers limit requests and tokens per minute. The client pauses after every non-cached response (-write-gap) to stay under the limit, and waits longer after each page change (-settle); the pauses are the same for every arm and are not part of any latency. A rate-limit refusal would show up as an error.
- The plain-ttl arm expires entries after its TTL, so what it serves depends on how far apart requests are in time. Its TTL and the pauses differ from the mock run (see "Settings"), so its numbers are not comparable one for one with the mock run's plain-ttl column.
- The plain arm runs Bifrost with the semantic-cache settings of docker/bifrost-config.real.json, which are the same as in the mock run (see "Settings"), not a tuned setup.
- The companion's evidence fetches (an HTTP GET of the demo page) are not model calls and are not counted here.
- Cost figures multiply measured call counts by prices that are assumptions given on the command line. They are an illustration, not a measurement.
- The page is edited in place by this command, which needs exclusive use of it and of the stack. The same file is restored byte for byte at the end of every arm and on exit.
